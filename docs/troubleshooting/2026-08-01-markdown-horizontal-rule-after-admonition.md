# MkDocs 提示块后的 Markdown 分隔线

## 症状

Flink 专题的 L01–L07 文档中，紧跟在 `???` 或 `!!!` 提示块后的 `---`
没有渲染成水平分隔线，而是直接显示为文本。其他位置的分隔线可能正常。

## 影响范围

所有经过专题渲染器处理、且在 MkDocs 提示块后紧接 Markdown 内容的文档。

## 根因

渲染器会先把 MkDocs 提示块转换成原始 HTML 的 `details` 或 `aside` 元素。
如果生成的 HTML 后面没有空行，Markdown 解析器会把紧随其后的 `---` 视为
同一个 HTML 块的一部分，而不是 thematic break。

## 修复

在转换后的提示块与后续 Markdown 内容之间统一补一个空行。这样文章源文件
仍保持原样，不需要逐篇给每个 `---` 手工插入空行。

## 验证

- 为提示块后接 `---` 的场景增加渲染回归测试。
- 确认 `---` 输出为 `<hr>`，后续标题仍正常输出。
- 运行专题静态构建检查。
