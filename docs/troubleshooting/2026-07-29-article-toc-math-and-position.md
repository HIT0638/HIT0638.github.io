# Article TOC math labels and floating position

## Symptom

Inline formulas in article headings rendered correctly in the article body but
appeared as literal text such as `\omega` in the table of contents. The TOC
also sat at the upper edge of the article instead of floating near the left
side of the viewport center.

## Affected scope

- `app/markdown.ts` and the rendered `ArticleTocItem` data
- `app/article-toc.tsx` label rendering
- Desktop article layout styles in `app/globals.css`

## Root cause

The outline extractor intentionally kept a plain-text heading label for IDs
and accessibility. The client TOC rendered that text directly, while the
article body separately passed the Markdown AST through `remark-math` and
`rehype-katex`. The two consumers therefore used different representations of
the same heading.

The desktop TOC used `position: sticky; top: 32px`, so its position was tied to
the top of the article layout rather than the viewport center.

## Final fix

After the existing Markdown pipeline transforms the AST, the renderer now
collects the inner HTML of the rendered H2-H4 nodes and attaches it to the
corresponding TOC item. The TOC keeps the plain text for IDs, labels, and ARIA
attributes, but displays the trusted HTML generated by the same KaTeX pipeline.

On desktop, the TOC is a fixed, narrow left rail centered at `top: 50%` with
an internal max-height and scroll area. Its left edge follows the article
container, while the article explicitly stays in grid column 2 because a fixed
element no longer participates in grid auto-placement. The mobile breakpoint
restores normal flow and the collapsible TOC.

If the fixed rail is changed again, keep that explicit article column rule;
otherwise the article will be auto-placed into the narrow TOC track.

## Validation

- `npm run test:article-toc` — 9/9 passed, including a KaTeX TOC-label test.
- `npm run lint` — passed.
- `npm run build` — passed with all article routes prerendered.
- Local dev HTML contains KaTeX markup inside TOC links and the updated rail
  sizing/position rules.

## Maintenance note

Do not replace the rendered TOC label with plain `ArticleTocItem.text` when
changing the component. Keep the plain text field as the canonical fallback
and for accessible labels; keep `labelHtml` generated by the Markdown renderer
so formulas and inline Markdown stay consistent with the article body.
